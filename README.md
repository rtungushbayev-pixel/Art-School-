# Школа искусств и дизайна им. А. Кастеева — мобильное приложение

Мобильное приложение (React Native / Expo) для учеников и руководства
художественной школы.

## Возможности

**Ученикам:**
- расписание по неделям с датами: группа, преподаватель, кабинет, отмены и
  переносы занятий на конкретную дату
- «Профиль» → «Мои оплаты»: баланс (долг или переплата) и история начислений
  и оплат
- лента-коммьюнити (портфолио) — любой пользователь публикует фото своих
  работ, остальные видят публикации в общей ленте, ставят лайки и оставляют
  комментарии
- продажа работ: любой ученик или сотрудник может выставить картину на
  продажу (фото, цена, описание, контакты) — после проверки администрацией
  работа переносится на [kasteyevshop.kz](https://kasteyevshop.kz)
- объявления от администрации (с push-уведомлением)
- профиль ученика: направление, год начала учёбы, группы, отметка, куда
  поступил(а) / планирует поступать, счётчики работ и лайков
- портфолио: у каждой работы название, техника и год; до 6 избранных работ
  закрепляются в начале; экран «Все работы» с фильтром по технике. Если
  автор меняет текст уже проверенной работы, она снова уходит на модерацию
- достижения: конкурсы, выставки, награды с результатом и датой; сотрудник
  может отметить достижение как «подтверждено школой»
- push-уведомления: новые объявления, комментарии к вашим работам, решение
  модерации — каждую категорию можно отключить в «Профиль» → «Уведомления»

**Руководству:**
- та же лента-коммьюнити: публикация своих работ, лайки и комментарии наравне с учениками
- управление группами: создание групп, добавление/удаление учеников, назначение преподавателя
- расписание занятий по группам (создание, редактирование, удаление) и
  общее «Расписание школы» во вкладке «Группы»: отмена или перенос занятия
  на конкретную дату с комментарием для учеников
- учёт оплат («Профиль» → «Оплаты учеников»): баланс каждого ученика, общий
  долг, начисления (одному ученику или всей группе) и принятые оплаты
  (наличные / карта / перевод). Деньги принимаются вне приложения — здесь
  только учёт
- рассылка объявлений (всем / ученикам / сотрудникам / конкретной группе), с редактированием и удалением
- учёт посещаемости по группам и датам
- модерация загруженных в портфолио работ и объявлений о продаже (одобрить / отклонить)

## Стек

- Expo (React Native, TypeScript), React Navigation
- Supabase: Postgres + Auth + Storage + Row Level Security

## Запуск

1. Создайте проект на [supabase.com](https://supabase.com).
2. Выполните SQL-миграции из `supabase/migrations` (SQL editor в Supabase
   Studio или `supabase db push`, если используете Supabase CLI), по порядку:
   `0001_init.sql`, `0002_storage.sql`, `0003_marketplace.sql`,
   `0004_homework_attachments.sql`, `0005_security_fixes.sql`,
   `0006_notification_settings.sql`, `0007_push_security.sql`,
   `0008_staff_role_assignment.sql`, `0009_private_data.sql`,
   `0010_student_portfolio.sql`, `0011_payments_schedule.sql`,
   `0012_parents_progress.sql`, `0013_support.sql`, `0014_signup_account_type.sql`,
   `0015_friends.sql`, `0016_friend_suggestions.sql`,
   `0017_parent_link_requests.sql`, `0018_support_categories.sql`,
   `0019_school_roster_codes.sql`, `0020_security_hardening.sql`,
   `0021_rate_limits_blocks_storage.sql`, `0022_post_photo_limit.sql`,
   `0023_admin_role.sql`, `0024_ai_moderation_reports.sql`.
3. Скопируйте `.env.example` в `.env` и укажите `EXPO_PUBLIC_SUPABASE_URL`
   и `EXPO_PUBLIC_SUPABASE_ANON_KEY` из настроек вашего проекта Supabase.
4. Установите зависимости и запустите:

   ```bash
   npm install
   npm run start
   ```

   Откройте приложение в Expo Go (iOS/Android) или через `npm run web`.

## Роли и данные

Роли: `student` (ученик), `parent` (родитель), `staff` (преподаватель),
`admin` (администратор). Регистрация только по коду из школы
(`school_roster`) или по приглашению сотрудника (`staff_invites`, создаёт
администратор). Первого администратора назначают в SQL Editor:

```sql
update public.profiles set role = 'admin' where id = '<uuid пользователя>';
```


Роль (`student` / `parent` / `staff`) хранится в `profiles.role`. При
регистрации человек выбирает «Ученик» или «Родитель» и группу: ученик сразу
попадает в группу (`group_members`), родитель видит расписание и сообщения
выбранной группы (`parent_groups`). Доступ родителя к данным конкретного
ребёнка открывает сотрудник, привязав ребёнка. Сотрудником человека делает другой
сотрудник кнопкой «Сделать сотрудником» на экране его профиля (RPC
`set_user_role`). Первого сотрудника нужно назначить один раз в SQL Editor:

```sql
update public.profiles set role = 'staff' where id = '<uuid пользователя>';
```

Группы, их состав и расписание управляются сотрудниками
прямо в приложении (вкладка «Группы»).

## Push-уведомления

Используется Expo Push Service — бесплатный, без Firebase/APNs-ключей на
старте. Схема:

- клиент получает Expo push-токен и регистрирует его через RPC
  `register_push_token`. Токены лежат в таблице `push_tokens`, которую
  клиент не может ни читать, ни писать напрямую — чужие токены не
  утекают;
- после действия (комментарий, модерация, объявление) клиент вызывает Edge
  Function `send-push`, передавая **только событие и ID записи**
  (`{ event: 'post_comment', id }`). Функция по JWT определяет, кто
  вызывает, проверяет права (комментарий — только его автор; модерация и
  объявления — только сотрудники), сама находит получателей и составляет
  текст. Разослать произвольный текст произвольным людям через неё нельзя;
- каждое событие рассылается не более одного раза (таблица `push_events`),
  поэтому повторные вызовы не превращаются в спам.

Чтобы уведомления заработали:

1. Разверните функцию (нужен [Supabase CLI](https://supabase.com/docs/guides/cli),
   проект должен быть слинкован через `supabase link`):

   ```bash
   supabase functions deploy send-push
   ```

   `SUPABASE_URL` и `SUPABASE_SERVICE_ROLE_KEY` передаются в функцию
   автоматически, ничего дополнительно настраивать не нужно.

   Необязательно, но рекомендуется: включите в Expo
   [Enhanced Push Security](https://docs.expo.dev/push-notifications/sending-notifications/#additional-security)
   и сохраните access token как секрет функции
   (`supabase secrets set EXPO_ACCESS_TOKEN=...`) — тогда Expo не примет
   пуш без него, даже если кто-то узнает токен устройства.

2. Получение push-токена на устройстве требует EAS-проекта: выполните
   `eas init` (или `npx expo install eas-cli` → `eas init`), это добавит
   `extra.eas.projectId` в `app.json`. Без этого шага `getExpoPushTokenAsync`
   аккуратно завершится с предупреждением в консоли, а остальной функционал
   приложения продолжит работать как обычно.

3. Начиная с Expo SDK 53 получение **удалённых** push-токенов недоступно в
   обычном Expo Go — нужен [development build](https://docs.expo.dev/develop/development-builds/introduction/)
   (`eas build --profile development`) или production-сборка.

Точки отправки: новое объявление (по аудитории), новый комментарий к
работе (автору), решение модерации по работе/объявлению (автору).

Нажатие на уведомление открывает связанный экран: комментарий или решение
модерации по работе → публикация, решение по объявлению о продаже →
карточка товара, новое объявление → вкладка «Новости»/«Объявления». Это
работает и когда приложение было закрыто; если пользователь не вошёл,
переход произойдёт сразу после входа. Экран выбирается по полю `data.type`
уведомления (`src/lib/notificationRouting.ts`).

Настройки: в «Профиль» → «Уведомления» пользователь включает/выключает
каждую из трёх категорий (объявления, комментарии, модерация) — они
хранятся в `profiles.notify_*`; `send-push` пропускает получателей,
отключивших категорию события. Там же
показывается, если уведомления запрещены на уровне системы, с кнопкой
«Разрешить» / «Открыть настройки». После обновления функции её нужно
заново задеплоить: `supabase functions deploy send-push`.

## Сборка приложения (EAS)

Профили сборки описаны в `eas.json`: `preview` собирает APK для установки
на Android напрямую, `production` — сборку для магазинов. Идентификатор
приложения — `kz.kasteyev.artschool` (`app.json`); после публикации в
магазине его менять нельзя.

`.env` не попадает в сборку (он в `.gitignore`), поэтому адрес и ключ
Supabase задаются как переменные окружения EAS — один раз для каждого
окружения (`preview`, `production`):

```bash
npx eas-cli login
npx eas-cli init   # создаёт EAS-проект и добавляет projectId в app.json
npx eas-cli env:create --environment preview --name EXPO_PUBLIC_SUPABASE_URL --value https://xxx.supabase.co --visibility plaintext
npx eas-cli env:create --environment preview --name EXPO_PUBLIC_SUPABASE_ANON_KEY --value <anon key> --visibility plaintext
npx eas-cli build --platform android --profile preview
```

После сборки EAS даёт ссылку и QR-код для установки APK. Чтобы на Android
приходили push-уведомления, нужен ключ Firebase Cloud Messaging:
создайте проект в Firebase, добавьте Android-приложение с пакетом
`kz.kasteyev.artschool`, положите `google-services.json` в корень проекта
и укажите его в `app.json` (`android.googleServicesFile`), затем загрузите
ключ сервисного аккаунта (FCM V1) через `npx eas-cli credentials`.

## Продажа работ и kasteyevshop.kz

Прямой интеграции (API) с kasteyevshop.kz нет — у школы нет доступа к
личному кабинету продавца/API этого магазина. Раздел «Продажа» в
приложении — это внутренняя витрина: ученики и сотрудники размещают
объявления (фото, цена, описание, контакты), администрация школы проверяет
их во вкладке «Модерация» → «Товары на продажу», а затем вручную переносит
одобренные работы на сайт магазина. На карточке объявления есть кнопка
«Открыть kasteyevshop.kz» — просто открывает сайт в браузере.

## Дальнейшие шаги

- Домашние задания и сдача работ убраны полностью: школа не проверяет
  работы учеников в приложении. Миграция `0009_private_data.sql` удаляет
  таблицы `homework` / `homework_submissions` и снимает все политики с
  бакета `homework`, так что клиент к нему доступа не имеет.
- Если у школы появится API/доступ к личному кабинету kasteyevshop.kz —
  можно автоматизировать перенос одобренных объявлений на сайт вместо
  ручного переноса администрацией.
